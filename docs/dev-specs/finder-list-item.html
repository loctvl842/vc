Finder list item - dev spec

PM spec: docs/pm-specs/finder-list-item.md

Scan three more things per session (last real message in full, last branch, PR). Render each session as title / folder row / recap / last message, word-wrapped, folded to 3 lines unless selected. Search the recap and last message as substring-only through the matcher mechanism that already exists. Four phases, each mergeable alone.

Context

Gap. A row has title, project, cwd, counts and a recap (commit 80d10ee), but not the last message, branch or PR. format returns a fixed 2-3 rows and cuts with "…". The list calls format_fn(item, width) with no idea which item is selected, so a selected item cannot grow.

Why not Claude Code's own last-prompt? It is cut at about 200 characters (longest seen: 201) and once held /compact. It cannot give a "full message".

Orange boxes change. The matcher does not: recap and last message share the existing substring-only region.

Research

Repo

Nothing reads last-prompt, pr-link, gitBranch or isCompactSummary. Reuse: source.fit, source.location, fuzzy_len, the ranges mechanism. List callers of format_fn: height_of, render_visible only.

Built-ins and real data

  • last-prompt.lastPrompt: 95 sessions, cut at ~200 chars, not always a real message. Rejected as the source.
  • pr-link: {prNumber, prUrl, prRepository}, 9 sessions. gitBranch: main (68), HEAD (22), 14 sessions changed branch mid-session.
  • Not messages: isCompactSummary, [Request interrupted by user], tool results.
  • A skill call with arguments is stored as <command-args>; today it yields nothing.
  • No string word-wrap API in Neovim; window wrap would not give exact line counts for the fold and match rules. Rejected.

Decision: Reuse fit/location/fuzzy_len/ranges   Build wrap.lua and the scanner fields.

Decisions and PM spec gaps

Things the PM spec left open. Each is a default I chose; push back on any.

1. "Full" stops at 2000 characters. Every stored character is cached for every session; a pasted stack trace is not useful in a list. Longer text ends with "…". Median last message today: 69 characters.
2. A command with arguments is a message. /pm-spec Now I want... counts and shows the arguments. Bare /recap, /clear, /compact do not. Otherwise skill-driven sessions show an older message.
3. Not user messages: compaction summaries, interruptions, tool results, meta records.
4. "Same as the title" is checked after the 120-char title cut, so a one-message untitled session does not show its prompt twice.
5. The blank separator row belongs to the item and sits inside the selected highlight (reads as padding). To verify visually in Phase 4.
6. Match extension uses the first match of a message when several words are typed; it extends to that line, not to every match.

Phases

Phase 1 - Scanner data (no UI change)

Rows carry what the list needs. Smallest slice: scan.lua, cache.lua, tests.

  1. Message helper - user_text returns command-args text for commands with args; cut at 2000 with "…". Risk M: title fallback changes for sessions that began with a skill call.
  2. Last real message - skip isCompactSummary; keep the last 5 non-tool-result user lines (plain find, no decode); decode newest first, skip interruptions; drop if equal to the title's source. Risk M: scanner speed, benched in Phase 4.
  3. Branch and PR - last counted line's gitBranch (nil for empty or HEAD); latest pr-link number.
  4. Row fields - last_prompt, branch, pr; recap cap = 2000.
  5. Cache v3 - one rescan on first launch.
  6. Tests - fixtures and specs for each rule above.

Phase 2 - Wrapped, folded rows

The PM spec layout on screen; search highlight on prose comes in Phase 3.

  1. wrap.lines(text, width) -> 1-based byte spans; break at spaces; split over-wide words at a character boundary; never split UTF-8; width by display columns. Risk M: wide characters.
  2. format rewrite - title, folder row (full path left-cut, chips, stats right), recap rows (Recap › ), message rows (You › ), blank row; fold to 3 lines unless selected; max_rows cuts with "…"; text width = width - 12.
  3. List - pass {selected = idx == cursor, max_rows = win height} to every format_fn call so scrolling sees the open item's real height. Risk M: offset/cursor logic.
  4. Highlights - ListLabel (dim), ListPrompt (normal), recap dim.
  5. Tests - wrap spec; fold/open; re-fold on move; taller than window; two-row item; chips; narrow folder.

Phase 3 - Search and highlight

Recap and last message searchable (substring only), matches visible and highlighted.

  1. Search text - title location recap message; fuzzy_len = #title + 2 + #location; remember each field's start.
  2. Positions to rows - find field, then wrap span, emit one range per row (bytes incl. label), merge consecutive bytes. Risk M: byte math, tests assert the highlighted substring.
  3. Never hide a match - unselected message extends to the line of its first match, capped by max_rows.
  4. Tests - message-only word, recap-only word, scattered letters, match in line 5, two words, 'exact.

Phase 4 - Verify on real data

  1. Bench scripts/bench-index.lua before/after Phase 1; same range as before. Risk M
  2. Manual PM scenarios 1-8 on your sessions; light/dark; narrow window; the selected highlight over the blank row.
  3. Codemap via update-codemap.
