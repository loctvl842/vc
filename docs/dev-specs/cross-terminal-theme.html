Terminal Theme - dev spec

The finder gets its colors from the terminal instead of Neovim's built-in scheme. We turn termguicolors off, define every VCFinder* group with terminal palette indexes and a transparent background, and re-apply the few light/dark groups when 'background' changes. Neovim already detects the terminal's light/dark state, so no detection code is written.

PM spec: docs/pm-specs/cross-terminal-theme.md

Context

Problem. lua/vc/finder/highlights.lua links each group to a default-scheme group. Neovim turns on termguicolors by itself when the terminal supports it, so those links resolve to fixed RGB colors that ignore the terminal theme. Nothing reacts to 'background' changing.

Solution. Palette indexes (0-15) and NONE backgrounds, plus one OptionSet background autocmd. Highlights only; buffers and windows are untouched, so query, selection and scroll survive.

How the color gets from the terminal to the finder

Research

Repo. Searched colorscheme|background|theme|highlight|nvim_set_hl|winhl|termguicolors|OptionSet. All color logic lives in highlights.lua; windows consume it via winhl. No colorscheme, no termguicolors/background setting, no highlight test. Reuse group names, setup() entry point and the augroup style of finder/autocmds.lua.
Built-ins. Neovim 0.12.6: termguicolors is auto-enabled (must be set off); with it off, cterm* indexes 0-15 are the terminal's palette and NONE keeps its background; 'background' is detected and updated on theme change (mode 2031); OptionSet background fires. Use these, Build only the table and one autocmd. No OSC queries.

Phases

Phase 1 - Palette colors: finder follows the terminal theme

  1. Turn off 24-bit color lua/vc/init.lua risk: medium
    Add vim.o.termguicolors = false to set_ui_options. Risk: Claude Code's RGB colors in the terminal buffer are downsampled to 256; checked in Phase 3.
  2. Define groups from the palette lua/vc/finder/highlights.lua risk: medium
    Replace the links with cterm specs per the palette map, default = true. Risk: index 8 can equal the background in some themes (dim text vanishes).
  3. Unit specs test/finder/highlights_spec.lua low
    No ctermbg on Normal, accent is 6, selected row 0 on dark, no group links to a default-scheme group.

Phase 2 - Live light/dark

  1. Re-apply on background change lua/vc/finder/highlights.lua low
    Augroup VCFinderHighlights, OptionSet on background calls apply(). Highlights only, so query, selection and scroll are untouched.
  2. Spec for the switch test/finder/highlights_spec.lua low
    Type a query, set background=light, assert selected row is 7 and query/selection unchanged; default is dark.

Phase 3 - Verify in real terminals and document

  1. Manual run risk: medium
    PM scenarios 1-6 in Ghostty (Monokai Pro + a light theme), inside tmux, and with TERM=xterm. Compare Claude Code rendering before and after in the terminal buffer. If dim text, selected row or Claude Code colors fail, use the fallback below.
  2. Codemap docs/CODEMAP/ low
    Run /update-codemap.

Decision for you

OptionWhatTrade-off
A. Terminal palette (recommended)termguicolors off, cterm 0-15, transparent bgSimple, robust, palette changes follow with no code, no OSC queries. Selected row and dim use palette slots, not a computed tint. Claude Code RGB is downsampled to 256 colors.
B. Query the terminalKeep termguicolors; read palette/bg/fg via OSC 4/10/11, blend tint and dim, set g:terminal_color_NExact tints and Claude Code colors; needs async queries, timeout, tmux passthrough, and a fallback to A anyway.

Phase 3 decides: if A passes the manual checks, B is not built. Otherwise B becomes a follow-up dev spec and Phases 1-2 stay as its fallback.

Testing

  • Headless: make test, make test SPEC=test/finder/highlights_spec.lua, make lint.
  • Bench: n/a, no hot path touched.
  • Manual: PM scenarios 1-6. Scenario 3: flip Ghostty light/dark with the finder open. Scenario 5: TERM=xterm in tmux without focus events.

Success criteria

  • Dark themed terminal: finder background indistinguishable from the terminal's.
  • Light themed terminal: all text, hints and selected row clearly readable.
  • Two terminals with different themes give visibly different finders, each matching its own.
  • Theme or light/dark change with the finder open repaints without losing query, selection or scroll.
  • After quitting Claude Code following a theme change, the finder shows the new theme.
  • No theme setting, install step or restart needed.
  • Terminal not reporting light/dark: finder opens dark and readable, no error.
  • Matched letters, selected row, dim text and error red stay distinguishable in every theme tested.
  • make test and make lint pass; no VCFinder* group links to a default-scheme group.
  • Claude Code in the terminal buffer shows no visible color regression.
