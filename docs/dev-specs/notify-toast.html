notify-toast - dev spec

Copy BeastVim's toast lib as vc.toast (no progress), add its colors to the shared notify highlights, and make vc.notify.notify send INFO to the toast while WARN and ERROR stay cards.

PM spec: docs/pm-specs/notify-toast.md

Context

Every message is a boxed top-right card. Routine INFO needs a lighter one-line bottom-right style with repeat merging. vc.notify.notify is already the single entry for vim.notify and the ui2 message routing, so one level check is enough; callers do not change.

How it flows

Green = copied from BeastVim, orange = new or changed.

Research

Repo. Searched notify.notify, vim.notify, highlights, VimResized. One dispatch point exists; vc.animate, vc.finder.view, vc.theme and the highlights refresh are reusable. Existing test/notify/stack_spec.lua uses INFO for cards and must move to WARN. Reuse.
BeastVim toast. Self-contained except View/animate/Theme. Decision: Reuse (copy); Build only dispatch, shared highlights, stack cap, resize relayout. Not copied: progress, health, demo test, update/dismiss_id, segments.

Testing strategy

  • Headless: make test, make lint with new and updated specs.
  • Bench: n/a.
  • Manual: PM scenarios 1-7 in tmux: bottom-right line, x3 merge, ellipsis at 40 columns, WARN card, light/dark flip.

Success criteria

  • INFO is one dim line at the bottom right, no box; WARN and ERROR stay top-right cards.
  • Five identical INFO messages show one line with "x5".
  • Multi-line messages on one line; long ones end with an ellipsis; 40 columns stays readable.
  • Colored icon, terminal palette in light and dark; fade in/out; gaps close.
  • Typing uninterrupted; background messages show with no error; no "Press ENTER".
  • make test and make lint pass.
