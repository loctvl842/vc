Session Finder - Dev Spec

VimClaude only ever shows two screens: the finder, or Claude Code in a full-window terminal. We build a cached index over every ~/.claude/projects/*/*.jsonl, a transcript-to-markdown preview, a trimmed copy of BeastVim's finder wired to that one source, and a loop that launches claude --resume and returns to the finder when it exits.

PM spec: docs/pm-specs/finder-init.md - 5 phases, each mergeable alone.

How the pieces fit

Context

Problem. The repo has only skill scaffolding and STRATEGY.md. There is no config, no session reader and no finder; Claude Code offers no cross-project listing. Solution. nvim starts straight in a full-screen finder fed by a persistent index. Enter hands the window to claude; exit returns to the finder. BeastVim code is copied and trimmed, never required.

Research

Repo search. Searched the working tree: only .claude/, STRATEGY.md, PM spec. No code, no CODEMAP (skipped, nothing to map; run update-codemap after Phase 1). Reuse: none.
Built-ins and existing code.
  • Use: Neovim 0.12.6 vim.uv, vim.json, jobstart{term=true}, stdpath("cache").
  • Reuse by copy-and-trim: BeastVim finder (~5.6k lines) - matcher, score, topk, match_hl, layout, render, queue, session, keymaps, ui/{input,list,preview,backdrop,hint}. Not taken: sources, chains, gh/gl, diff, live-grep index.
  • Build: scan, index, cache, transcript renderer (nothing suitable exists).
  • Format facts: typed JSONL lines (user, assistant, ai-title, large api-request* records to ignore). The folder name is a lossy encoding, so the real folder comes from each record's cwd. Store here: 176 files, 187 MB, 25 projects.
  • Resume: claude --resume <id> found a session from an unrelated directory (/tmp). That check used -p, which ran a real model turn and appended to this very session's transcript; re-verify the interactive case on a throwaway session in Phase 4.

Phases

Phase 1 - Session index risk: medium

Reliable metadata for every session, fast on warm start. No UI.

  1. Row scanner sessions/scan.lua: cwd from first user/assistant record, title from last ai-title (else first prompt, else "(untitled)"), last timestamp, message count (all non-sidechain user + assistant records, tool calls and results included = full conversation). Tolerates bad lines and empty files.
  2. Cache sessions/cache.lua: keyed by path, valid while size+mtime match; corrupt/old file rebuilt.
  3. Index walk sessions/index.lua: top-level jsonl only, cached rows first, changed files rescanned off the main loop, vanished files dropped, cwd_exists computed. Never writes under ~/.claude.
  4. Tests Makefile, test/sessions/*: titled, untitled, empty, corrupt line, deleted folder, subagent subdir.

Phase 2 - Transcript renderer risk: medium

Whole conversation as readable markdown. Depends on Phase 1 step 1.

  1. Renderer transcript.lua: You / Claude sections. Tool calls, tool results and thinking are kept in full, and each consecutive run is recorded in a fold map. Only non-conversation records are skipped. Never truncates, yields in chunks. The preview turns the map into auto folds (foldmethod=expr, foldlevel=0, fold text "▸ 4 tool calls" / "▸ thinking"); za/zo/zR work, the user never creates folds.
  2. Tests test/transcript_spec.lua: string vs array content, tool runs, thinking, fold map matches runs, tool text present, 2k-turn session keeps its last line.

Phase 3 - Finder UI risk: high

Trimmed BeastVim finder over the one source. Depends on Phases 1-2.

  1. Copy and trim finder/*: rename requires, drop View/chain/gh/gl/diff/live-grep/level. Gate: no require("beast left. Small commits, tests green at each.
  2. Sessions source finder/source.lua: "+ New session" only on empty query; match on title + project only; row format per PM spec incl. "(folder gone)"; preview from transcript.lua with its auto folds applied, all closed on open.
  3. Full-screen layout and keys: no backdrop or margin; <C-n>/<C-p>, <CR>, <Esc> = :qa; Enter on no rows is a no-op; selection resets on query change.
  4. Tests test/finder/*.

Phase 4 - Two-screen loop risk: medium

Enter opens Claude Code, exit returns to the finder. Depends on Phase 3.

  1. Claude runner claude.lua: Claude Code runs in a Neovim terminal buffer (a PTY owned by this Neovim).
    1. Close the finder so one window remains; put a scratch buffer in it (bufhidden=wipe, no columns, laststatus=0, showtabline=0).
    2. jobstart(cmd, {term=true, on_exit=cb}), then startinsert so keys go straight to Claude Code.
    3. Resume = cd <cwd> && exec claude --resume <id> run via {shell, "-c", 'cd "$1" && exec claude --resume "$2"', "vc", cwd, id}. cwd and id are positional args, never interpolated, so odd paths are safe; exec makes Claude's exit end the job.
    4. New session = same shape with claude only, cd to getcwd().
    5. Folder gone: skip the cd, print the notice line first, then exec claude --resume <id> from getcwd().
    6. on_exit is scheduled to the main loop and calls back_to_finder(). Non-zero exit or missing claude shows one message above the finder.
    7. Neovim's own cwd never changes (the cd is inside the child shell).
  2. State machine vc/init.lua, init.lua: finder on VimEnter; after exit wipe the terminal buffer, :only, reopen finder with empty query and refreshed index; no way to open the finder by hand; no dashboard or intro.
  3. Integration tests test/loop_spec.lua with a fake claude: window count is 1 at every point.

Phase 5 - Performance and polish risk: low

"Opening stays fast." Depends on Phases 1 and 3.

  1. Bench scripts/bench-index.lua: 5,000 synthetic sessions; report cold, warm first paint, incremental refresh.
  2. Tune only if warm first paint misses ~100 ms: head/tail windows for metadata, batched cache writes.
  3. Pixel pass against docs/pm-specs/finder-init.html: alignment, truncation, selection bar, empty state.

Decisions (settled in review)

Ctrl-C. Keep Claude Code's own quit behavior (first Ctrl-C interrupts, second or /exit quits). The finder returns whenever the process exits, however it exits. Agreed.
Message count. The row shows the size of the full conversation (all user + assistant records, tool calls and results included), and the preview shows that same full conversation. My reading of your note: please correct me if you meant counting raw file lines.

Testing strategy

  • Headless: make test, one spec per module, plus a grep-gate test for require("beast.
  • Bench: nvim --headless -l scripts/bench-index.lua after touching sessions/*.
  • Manual: PM spec scenarios 1-8 against the real store, then confirm nothing under ~/.claude changed.

Success criteria

  • All-project list, newest first; "New session" first only on empty query
  • Typing narrows by title/project; preview follows highlight and scrolls to the last message
  • Tool calls, results and thinking are in the preview, auto-folded and closed on open, openable with fold keys
  • Enter continues a session or starts a new one, Claude Code as the only window
  • Deleted-folder session continues from the current directory with a notice
  • Esc exits; quitting Claude Code returns to a refreshed finder; no editor buffer ever visible
  • Appears instantly with thousands of sessions (bench gate)
  • No write under ~/.claude; no require("beast in lua/; make test green
