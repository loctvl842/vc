Terminal Theme

VimClaude takes its colors from the terminal it runs in. Whatever theme the terminal uses (for example Monokai Pro), the finder looks like it belongs there, and when the terminal switches theme or flips between light and dark, the finder follows on its own. There is nothing to set up.

Problem

The finder is drawn in Neovim's built-in default colors, which know nothing about the terminal. In a themed terminal it looks like a foreign window: a different background shade, clashing accents, and in a light terminal text that can be hard to read. Fixing it today means picking, installing and maintaining a matching theme by hand, and redoing that whenever the terminal theme changes.

Why now: the finder is the only screen besides Claude Code, and Claude Code already matches the terminal. The finder is the one visual seam left.

Target behavior

The finder uses the terminal's own background, text color and palette. Nothing is chosen inside VimClaude.

Scenarios

1 - First launch in a themed terminal
UserHas a dark terminal themed "Monokai Pro" and starts VimClaude.
SeesThe finder opens already in Monokai Pro colors. No flash of default colors, no setup step.
UserTypes a query.
SeesMatched letters, selected row and preview colors all come from the same theme.
2 - Same finder, different terminal
UserOpens VimClaude in a second terminal with a pale light theme.
SeesA light finder with dark text, readable everywhere, with that terminal's accents.
3 - Terminal flips light/dark while the finder is open
UserHas the finder open in a dark terminal.
SeesDark colors.
User(or macOS at sunset) switches the terminal to its light theme.
SeesThe finder repaints light. Query text, highlighted row and preview scroll position stay where they were.
4 - Theme changes while Claude Code is open
UserIs inside a Claude Code session when the terminal theme changes.
SeesClaude Code changes with the terminal, since the terminal draws it.
UserQuits Claude Code.
SeesThe finder returns in the new theme, no stale colors.
5 - Terminal cannot report its theme (edge case)
UserStarts VimClaude in a terminal or multiplexer that does not say whether it is light or dark.
SeesA dark scheme using the terminal's own palette. No error, readable text.
UserTerminal later starts reporting a light theme.
SeesThe finder switches to light at that moment.
6 - Terminal with very few colors (edge case)
UserRuns VimClaude in a terminal that supports only the basic 16 colors.
SeesThe finder still follows the terminal palette. Selected row and borders stay visible, with fewer shades.

Behavior rules

  • The user never picks, installs or configures a theme for VimClaude. There is no setting for it.
  • The finder background is the terminal's own background, so there is no seam at the terminal edge.
  • Colors always come from the terminal's palette, never a fixed set baked into VimClaude. Two terminals with different themes give two different-looking finders.
  • Meaning stays constant across themes: title and prompt are accent, matched letters highlight, project/time/count dim, a missing project folder error red, "You" and "Claude" two distinct colors.
  • A theme change never resets the query, selection, scroll position or open preview.
  • While Claude Code is full-window, VimClaude draws nothing, so the terminal theme shows through unchanged.
  • If light/dark cannot be known, assume dark.
  • The cursor stays hidden in the list and visible in the query, as today.

Success criteria

  • In a dark themed terminal the finder background is indistinguishable from the terminal background.
  • In a light themed terminal all text, hints and the selected row are clearly readable.
  • Two terminals with different themes show visibly different finder colors, each matching its own terminal.
  • Changing the terminal theme or light/dark mode with the finder open repaints it without losing query, selection or scroll.
  • After quitting Claude Code following a theme change, the finder shows the new theme.
  • No theme setting, install step or restart is needed.
  • When the terminal does not report light/dark, the finder opens dark and readable with no error.
  • Matched letters, selected row, dim text and error red stay distinguishable from normal text in every theme tested.

Out of scope

  • Choosing or switching themes from inside VimClaude: the terminal owns the theme.
  • Custom color overrides for parts of the finder: can be added later if needed.
  • Theming Claude Code itself: it has its own setting and is drawn by the terminal.
  • Terminals that cannot show colors at all.
