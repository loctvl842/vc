Preview in Claude Code style

The preview pane shows a past session the way Claude Code itself draws it: > prompts, ● replies, real bold / italic / headings / lists / inline code, highlighted code blocks, one-line tool calls and colored diffs. Browsing sessions should feel like scrolling the real screen, not a text dump.

Scenarios

1 - Glance at a session in the list

Move the selection over a session. Preview fills with > prompts, ● replies, styled text, one-line tool calls. No raw markdown symbols.
Move to another session. New conversation replaces it, same look, no flash of unstyled text.

2 - Reply with mixed markdown

Heading, bullets, bold, inline code. Heading bold, bullets use a glyph, inline code in its own color without backticks. Wrapped list lines align under the item text.
Reply narrower than the pane. Text wraps at the edge keeping the ● hanging indent.

3 - Code in a reply

Lua block. Dim language name above; keywords, strings, numbers, comments in different palette colors.
Unknown or no language. Still looks like code (indent, code color), without syntax colors.

4 - Tool activity

Several calls in a row. Each is one ● Name(args) line with the first lines of its result; long ones end in … +N lines.
Open the fold. Full result appears in place, dimmed, under its call. Closing returns to the summary.
A failed call. Result in the error color from the first line.

5 - A file edit

Update(path). Count line, then changed lines with line numbers: removed on an error band, added on a green band, context plain.

6 - Terminal flips light / dark with a preview open

Switch the terminal theme. All preview colors repaint in place. Scroll position and open folds stay.

7 - Very long session

Select a session with thousands of messages. The top appears immediately and the rest fills in. Moving away cancels the work. Typing in the query box is never delayed.

8 - Odd content

Table, image, unstyleable markdown. Tables keep aligned rows and columns with box lines; images show as [image]; everything else plain. Nothing is dropped.

Behavior rules

  • User prompts start with >, Claude's text with ●; continuation lines sit under the text.
  • Markdown markers (**, *, backticks, #, link brackets) are never shown once their style is applied.
  • All colors come from the terminal palette and flip with light / dark; no fixed hex values.
  • Bold, italic, underline, strikethrough use terminal text attributes, so they work wherever Claude Code works.
  • Tool results show only the first few lines; the rest is folded and opens with the usual fold keys.
  • Thinking is closed by default.
  • Every tool call line is always visible; only its long output is folded.
  • Copying text from the preview gives readable text without markdown markers.
  • Preview stays read-only; selection and fold keys behave as today.
  • Resizing the finder re-wraps the text without losing position.

Success criteria

  • The preview and the same session in Claude Code read as the same screen: markers, hierarchy, emphasis.
  • No raw **, backticks, ## or link syntax in any reply.
  • Bold, italic, headings, lists, quotes, inline code, links, strikethrough each look distinct.
  • Code blocks are highlighted for common languages and still look like code when the language is unknown.
  • Every tool call is one line; results are summarised and expand in place.
  • File edits show as a colored diff with line numbers.
  • Dark and light themes are both readable; a flip repaints live.
  • Rapid selection changes never freeze typing or leave a half-styled screen.
  • Wrapped lines keep a straight hanging indent in replies, lists and quotes.

Decisions for you

1. Tool calls: one visible line each, or one fold per run like today?
  • Recommended: one visible line per call, results folded. This is what makes it look like Claude Code, and the call lines are what you scan to remember a session. Cost: tool-heavy sessions get longer.
  • Keep one fold per run: shorter, but the call names are hidden until opened.
2. Thinking
  • Recommended: ✻ Thinking… folded (same as what the preview shows today).
  • Hide it entirely.
3. Sub-agent messages
  • Recommended: keep hidden, as today.
  • Show as a nested, indented block.

Reference captures needed

The look above is from how Claude Code is known to draw a transcript. Screenshots from your terminal are the ground truth for the details. If you open Claude Code on a few sessions, I need:

  • A user prompt (chevron color, background band, multi-line wrap)
  • A reply with a heading, bold, italic, inline code, bullet list, numbered list and a quote
  • A fenced code block (language label, indent, colors)
  • A Bash call with long output (the … +N lines line) and one that failed
  • An Edit/Update diff and a Write call
  • A thinking block, opened and closed
  • A table, and a todo list, if any session has them

Out of scope

  • Live updating of a running session - the preview shows the file as of selection.
  • Inline images or other media (placeholder only).
  • Mouse interaction on links or code.
  • Claude Code's input box, status line, permission prompts - only the conversation.
  • Sub-agent transcripts as separate panes - deferred until the main look is right.
