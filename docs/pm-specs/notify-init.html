notify-init

Every message Neovim would print at the bottom of the screen (errors, warnings, info) becomes a small card in the top right, in BeastVim's notification style. The "Press ENTER or type command to continue" prompt never appears.

Problem

VimClaude has no message area. A stray key in the read-only preview makes Neovim stop everything:

E21: Cannot make changes, 'modifiable' is off
Press ENTER or type command to continue

The finder or Claude Code is pushed up or covered, nothing responds until Enter, then the screen redraws. Same for any other error or warning.

Why now: the finder and Claude screen are meant to be uninterrupted, and messages are the only feedback the user gets, so they need a place that does not take over the screen.

Target behavior

State 1 - one error, user is in the finder
┌ Sessions ─────────────────────────────────┬──────────────────────────────┐
│ > fix                                     │  ┌────────────────────────────┐
│                                           │  │  ERROR                     │
│ ▌ Fix flaky login test                    │  │ E21: Cannot make changes,  │
│   ~/work/api-server - main                │  │ 'modifiable' is off        │
│                                           │  └────────────────────────────┘
│   Add retry to the sync job               │  (preview content continues)
│   ~/work/sync - feat/retry                │
└───────────────────────────────────────────┴──────────────────────────────┘
(no "Press ENTER" line, the bottom of the screen is untouched)
State 2 - several messages (newest at the bottom of the stack)
                                          ┌────────────────────────────────┐
                                          │  WARN                          │
                                          │ Hit BOTTOM, continuing at TOP  │
                                          └────────────────────────────────┘
                                          ┌────────────────────────────────┐
                                          │  ERROR                         │
                                          │ E21: Cannot make changes,      │
                                          │ 'modifiable' is off            │
                                          └────────────────────────────────┘
State 3 - a long message (more than 10 lines)
                                          ┌────────────────────────────────┐
                                          │  ERROR                         │
                                          │ Error executing Lua callback:  │
                                          │ ...line 1                      │
                                          │ ...line 2                      │
                                          │ ... (first 10 lines only)      │
                                          └────────────────────────────────┘
State 4 - narrow terminal (fewer than 84 columns)

Cards shrink to fit: never wider than the terminal minus a 2-column margin on the right, text wraps inside.

Card details
  • Title row: icon + level word (ERROR, WARN, INFO), colored from the terminal's own palette.
  • Body: message text, wrapped to the card width. Up to 80 columns wide, drawn above finder, preview and Claude Code.
  • Fades in, stays a few seconds, slides out to the right. Cards below move up to close the gap.

Scenarios

1 - A key tries to edit the read-only preview (the reported case)

  1. In the finder the user moves into the preview and presses x. Nothing moves or gets covered. A card fades in at the top right: "ERROR E21: Cannot make changes, 'modifiable' is off".
  2. The user keeps typing (no Enter needed). Keys work as before; the card does not take focus.
  3. About 3 seconds later the card slides out and disappears.

2 - Several messages at once

  1. Two problems happen within a second. Two cards appear one after the other, staggered, the older on top.
  2. They disappear oldest first; the remaining card moves up.

3 - Message while Claude Code is on screen

  1. Claude Code runs full screen and Neovim raises a warning. A card shows top right over the output. Claude Code keeps focus and the user's typing.
  2. The card expires and slides out; Claude Code output is unchanged underneath.

4 - The same message repeats

  1. The user presses x in the preview five times quickly. Five cards appear, stacked from the top.
  2. If the stack would run past the bottom of the terminal, only the newest cards that fit are kept; older ones slide out early.

5 - Very small terminal

  1. The terminal is 40 columns wide and a message arrives. The card is 38 columns wide with wrapped text, still readable.

6 - Message with nothing to say

  1. Neovim emits an empty message, or a search count like "[3/12]". No card appears (the finder shows its own counts).

Behavior rules

  • Every message Neovim would print at the bottom goes to a card instead: errors (E-numbered, Lua errors, failed commands), warnings and plain info. Nothing prints in the old place; the "Press ENTER" prompt never appears.
  • Level: errors are ERROR, warnings are WARN, everything else is INFO.
  • Multi-line messages keep their line breaks; more than 10 lines are cut after the 10th.
  • Notices from anything else in the editor (a plugin, a background task) use the same cards.
  • Cards never take focus and never steal keys.
  • A card stays about 3 seconds. If the user clicks into one with the mouse, it stays until focus leaves, then goes 2 seconds later.
  • Many cards in quick succession are staggered so they do not all pop in at once.
  • Background messages (timers, job output) show safely and never cause an error themselves.
  • Colors follow the terminal palette and update on light/dark switch, like the finder. No fixed color values.
  • Cards must not flicker or redraw the finder when they appear or disappear.
  • Search: a failed search shows one card "Pattern not found: <pattern>" (WARN), not two; wrapping shows "Hit BOTTOM, continuing at TOP" (or the reverse).

Success criteria

  • Pressing an editing key in the read-only preview shows the E21 text as a card in the top right.
  • "Press ENTER or type command to continue" never appears, in the finder or in Claude Code.
  • The finder (list, input, preview) is never pushed or covered by message text.
  • Typing continues uninterrupted while a card is visible.
  • Cards are colored by level and use the terminal palette in light and dark.
  • Several messages stack without overlapping and close the gap when one leaves.
  • Messages longer than 10 lines are cut at 10.
  • A narrow terminal still shows a readable card.
  • A background message (e.g. from a timer) shows as a card with no error.

Out of scope

  • A message history window or :messages-style browser: cards are fire-and-forget (deferred until needed).
  • A key to dismiss all cards at once: cards expire on their own.
  • Per-message routing rules (hide certain messages): everything shows, except empty messages and search counts.
  • Sounds, OS-level notifications, or notifications from Claude Code's own output.
  • Command-line input (: commands): VimClaude does not use a command line.
