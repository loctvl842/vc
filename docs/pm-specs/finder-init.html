Claude Session Finder

One finder lists every Claude Code session from every project in a single list, newest first. Typing narrows it, the preview shows the whole conversation, and Enter continues that session in Claude Code. There are only two screens: the finder and Claude Code. Quitting Claude Code brings the finder back. The mockup below is live: try it.

Try it

Click inside the finder and type. Keys: Ctrl-n/Ctrl-p or arrows to move, Enter to open, Esc to exit. Inside Claude Code, Ctrl-C quits and returns to the finder. Sample data only. Turn off "Pick elements" in the review panel (Alt+A) to use the mockup.

vimclaude - ~/work/api-server
$ (VimClaude exited to the shell)
Claude Sessions
>

Problem

Someone who uses Claude Code all day across many projects ends up with hundreds of past sessions, reachable only through the project they started in and named by an opaque id. Getting back to "that conversation about the login bug" means remembering the project, changing folder, and opening several cryptic entries.

Why now: every lookup breaks flow, and a cross-project finder is the one thing this configuration exists to provide.

Behavior rules

  • One flat list ordered by last activity, newest first. No project headers, no grouping, nothing hidden (empty or tiny sessions included).
  • Covers every project on the machine, never only the current one.
  • The query matches what a row shows (title, project); it never searches conversation text.
  • "New session" is first only while the query is empty; any query removes it, clearing brings it back.
  • First row is highlighted on open and after every query change.
  • Enter on no rows does nothing.
  • Missing project folder: still listed, continued from the current directory with a notice.
  • Preview always shows the whole conversation; tool calls collapse to a dim line.
  • Read-only: no delete, rename, or edit of any session.
  • Claude Code opens as the only window.
  • Only two screens exist: the finder or Claude Code. No editor view, no command to open the finder by hand.
  • Not in Claude Code means the finder is showing. Quitting Claude Code (Ctrl-C) shows it again, empty query, refreshed list.
  • Esc in the finder exits VimClaude.
  • Opening is fast at any session count; sessions started elsewhere show up on next open.

Success criteria

  • Sessions from all projects in one list, newest first
  • "New session" first with an empty query, absent once anything is typed
  • Typing narrows by title or project; preview follows the highlighted row
  • Preview of a very long session scrolls to its final message
  • Tool calls do not bury the dialogue
  • Enter on a session opens Claude Code, only window, in that session
  • Enter on "New session" opens a fresh session in the current directory
  • Deleted-folder session continues from the current directory with a notice
  • Esc exits VimClaude and changes nothing
  • Launching shows the finder immediately; no manual open step exists
  • No editor buffer is ever visible
  • Ctrl-C in Claude Code brings the finder back, refreshed, so browsing continues
  • The finder appears instantly with thousands of sessions
  • No action alters any session

Out of scope

  • Searching inside conversation text - the query matches what a row shows, by design
  • Grouping or filtering by project, hiding "boring" sessions - one flat list is the point
  • Delete, rename, edit, or tag sessions - the finder never writes
  • Any other source (files, grep, other agents' sessions)
  • A project picker for "New session" - it starts where Neovim is
  • An editor view or any third screen; Claude Code beside the editor or as a chat panel
