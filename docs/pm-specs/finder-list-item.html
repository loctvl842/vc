Finder list item

Show where each session left off, so the right one can be picked at a glance.

Each session shows its title, the full folder, the recap when Claude Code wrote one, and your last message - all in full, wrapped over as many lines as needed, and all searchable. Only the list changes; the preview is as it is today.

Problem

A list item is a title plus the last folder name. Two sessions on the same topic look identical, and two api-server folders cannot be told apart. The thing that answers "where did I leave off?" - your last message or the recap - is not shown and cannot be searched, so each guess costs a preview and a trip back.

Scenarios

1 - Pick a session by where it left off (happy path)
  1. Open the finder: every session shows title, full folder and last message; the first also shows its recap.
  2. "Fix flaky login test" ends with "replace the wait with polling, and then push the branch" - that is the one.
  3. Enter continues it in Claude Code, as today.
2 - Long messages open on selection
  1. Unselected, the long message shows 3 lines ending in "…".
  2. Select it: it opens to full length; sessions below move down.
  3. Move on: it folds back to 3 lines.
3 - Find a session by something you said
  1. Type "dana": only the session whose last message contains it remains; the match is highlighted, even on a wrapped line.
  2. If the match is beyond line 3 of an unselected session, that message shows lines up to the match.
4 - Recap search matches exactly, never loosely
  1. Type "plan": recaps and messages containing "plan" together match; titles and folders also match loosely, as today.
  2. Type "rmpl": scattered letters in a recap or message do not match.
5 - A session with nothing of its own
  1. No recap, no message the user wrote (only /clear or /resume): two rows - title, and folder with age.
6 - Narrow list
  1. Folders cut from the left ("…/jarvix-refactor-m4"), messages wrap narrower, branch/PR/age/count stay.
7 - Two folders with the same name
  1. ~/work/api-server and ~/old/api-server each show the full path.
  2. Type "old api": only the second remains.
8 - The folder is gone
  1. The folder row ends with "(folder gone)" in red, as today.

Behavior rules

  • Row order: title; folder, branch, PR, age, count; recap (if any); last message (if any). A blank row between sessions.
  • Full messages: wrapped at word boundaries; long words (URLs) are broken; line breaks and repeated spaces become single spaces.
  • Fold and open: unselected show at most 3 lines per message with "…"; the selected shows all. If taller than the list it is cut with "…"; the preview has everything.
  • A match is never hidden: a match past line 3 of an unselected session extends that message to the match.
  • Last message: the latest message you wrote. Command-only messages (/recap, /clear, /resume) and tool answers do not count. Hidden when none, or when identical to the title.
  • Recap: only when Claude Code wrote one (/recap or automatic); the latest; no placeholder; not marked out of date.
  • Folder: full path, home as ~, cut from the left with "…" when long; "(folder gone)" stays.
  • Branch and PR: last branch (hidden when unknown or detached); #8 when linked to a pull request.
  • Search: every typed word must match somewhere. Title and folder: letters spread in order, as today. Recap and last message: the word must appear contiguously as written (case-insensitive unless a capital is typed).
  • Highlight: matches highlighted everywhere, including wrapped lines.
  • Unchanged: "New session", the preview, key hints, ordering by last activity.

Decisions for you

1. Fold the unselected, open the selected (recommended)
vs. every message in full for every session - about 4 sessions per screen with long messages. Cost of folding: rows below move when the selection moves.
2. Chips: branch and PR (recommended)
vs. also +907 -60 lines changed - says whether real work happened, but the row is already full.
3. Recap above the last message (recommended)
vs. last message first. The recap is the broader answer; the message is the exact stopping point.
4. Recap without an age (recommended)
vs. "Recap · 2d ago". An old recap can mislead, but an age on every recap is noise.

Success criteria

Out of scope

  • Lines added/removed, cost, duration, model - none helps choose; the preview header is a better home.
  • Marking a recap out of date or showing its age - revisit if stale recaps mislead.
  • Claude's last answer in the list - the preview shows it.
  • A key to open one session's text without selecting it.
  • Generating a recap for sessions that have none.
  • Custom session names - none exist in the author's data yet.
